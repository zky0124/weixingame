# 手机与电脑适配规范

日期：2026年10月29日。状态：开发采用的界面初稿，具体尺寸通过实机调整。

用户要求：游戏首先面向手机，同时希望电脑测试时也有合适的界面与操作。本规范沿用阶段1横屏方向，共用玩法、数据和视觉风格，按可用空间调整UI，不额外开发一套电脑专用游戏。

## 基本原则

- 手机优先：必须用触摸完成所有必要操作，不依赖悬停、右键和键盘。
- 电脑可完整测试：鼠标可完成同样流程，键盘只是快捷方式，隐藏键盘也应可通关。
- 界面、战场镜头、逻辑坐标分开处理；不要把整个手机画面拉伸铺满大屏，也不按设备物理像素判断按钮大小。
- 所有下列数字是项目内部设计初值，不是平台强制规范。

## 画面与屏幕比例

1. 横屏参考画布1280×720，建筑和角色保持同一套比例。画面只能等比缩放，不能横向拉胖。
2. 核心可交战视口采用16:9，宽屏手机和超宽显示器额外区域用于环境延展或界面留白，不增加可交战范围，不让电脑因屏幕更宽而看见更多敌人。
3. 城市发展扩大的是已解锁地图及可拖动区域，不按设备改变兵种射程或单位/城市比例。无论手机还是电脑，默认镜头都能看到主城及必要进攻预警。
4. 手机使用可用屏幕宽度；电脑主界面内容最大宽度初值1600逻辑像素，超出后居中，背景自然延展，不继续把按钮无限放大。
5. 平板及16:10窗口利用剩余空间安排UI和环境留白，不裁掉主城或底部按钮。窄竖屏进入横屏提示，不在阶段1临时做第二套竖屏玩法；提示时暂停战斗与刷怪，产业收益按运行时间规则处理。
6. 屏幕旋转、窗口缩放只重排布局，不能重建战斗或重置奖励。恢复横屏后保持原有单位、血量与回合状态。

## 战场布局

| 区域 | 手机横屏 | 电脑宽窗口 |
| --- | --- | --- |
| 顶部 | 紧凑显示城池血量、铜币、回合；避开安全区和平台菜单 | 同样信息，可增加当前目标/操作提示，但不把调试数据混入普通界面 |
| 中央 | 优先留出战斗视野，角色选中与集火标记清晰 | 保持相同核心交战视口，不额外加敌情信息 |
| 左下 | 主城入口、招募入口；常用项展开后保持大点击区 | 可将招募和单位说明整理为紧凑侧栏 |
| 下方中部 | 英雄头像与当前选中状态，不密集堆满多排按钮 | 同样的英雄操作，可附快捷键提示 |
| 右下 | 明确的“迎敌”主按钮，旁边显示当前是否可迎敌 | 同样主按钮，可增加文字说明 |
| 敌人预警 | 边缘方向标记，点击可查看来袭信息 | 相同信息和规则，不能只在悬停时出现 |

弹窗、招募列表和说明打开后能关闭，返回入口位置稳定。操作界面不遮挡迎敌按钮和重要的主城受袭提醒。

## 主城内部与资料面板

- 手机：建筑槽位、建筑详情、升级与招募采用分层面板，必要时全屏；一屏不硬塞全部系统。
- 电脑：相同页面可使用左侧城市/列表、右侧详情的双栏布局，减少大片空白。
- 触控详情通过点击打开；电脑可加悬停预览，但点击仍能看到完整内容。
- 在主城内部战斗继续；常驻城池血条、受袭提示和“返回战场”按钮。返回不要求关闭多层弹窗。
- 详情面板中的升级、购买和关闭点击不向战场穿透，不误触选敌或集火。

## 按钮、字号与安全区

- 1280×720设计稿的正文建议32—36，关键数字36—44，次要说明不低于28设计单位；实际显示随缩放调整，不能照搬为物理像素。
- 在最小目标手机视口上，正文争取不低于约16个设备无关逻辑单位；按钮有效点击区至少44×44，迎敌/招募等常用按钮优先48—56高。图标可小，点击范围不能跟着缩到难以点中。
- 相邻主要按钮保留约8逻辑单位间隔。战场小单位额外扩大选取热区；选取范围重叠时选最近的可见候选并显示确认标记，不凭空更改单位体积或战斗碰撞。
- 刘海、圆角、底部手势区、平台右上角菜单按运行时安全区和平台菜单占位适配。装饰背景可延展到边缘，必要按钮和信息必须留在安全区内。
- 角色名、资源数和长描述允许折行/紧凑格式；不能被按钮遮住或在窄屏截断关键费用。

## 两种输入的对应

| 行为 | 手机 | 电脑 |
| --- | --- | --- |
| 查看单位/建筑 | 点按 | 左键单击 |
| 全军集火 | 双击敌人 | 左键双击敌人；可补充右键快捷集火 |
| 英雄独立攻击 | 点头像，再点敌人 | 点击头像，再左键点敌人 |
| 拖动地图 | 从战场空白区域拖动 | 从战场空白区域按住左键拖动 |
| 放大/缩小地图 | 双指开合；双指同向移动可拖动 | 鼠标指向地图后滚动滚轮，向上放大、向下缩小 |
| 返回/关闭 | 可见返回或关闭按钮 | 同样按钮；Esc可辅助 |
| 回到主城中心 | 可见回城按钮 | 同样按钮；Home可辅助 |

双击初值0.3秒；第一次点中敌人立即显示选中反馈，第二次点按确认集火。拖动移动超过约8逻辑单位后不再算点按或双击，避免拖地图时误集火。具体阈值实机调整。

电脑右键、Esc、Home为初稿辅助输入，不是手机功能的替代。按用户最新要求，v0.1.4起战场和主城内部均支持自由缩放，取代此前不开放缩放的初稿。

缩放初值范围65%—250%，围绕双指中心或鼠标位置缩放；单指/鼠标左键也可拖动。双指缩放、拖动及取消手势不触发点选、集火或建筑选址。UI与信息栏保持原有大小，主城与人物一同缩放，战斗逻辑、攻击距离和建筑占地不变。两张地图分别保留本次运行的视角，归中恢复100%；镜头不写入进度存档，重新打开回到默认视角。拖动范围有限制，避免无限拖离地图。

## 测试方式

开发时电脑内置“手机预览尺寸”切换，使用同一套UI组件和触控路径，不能只在1920×1080全屏上验收。

| 逻辑视口初值 | 用途 |
| --- | --- |
| 640×360 | 小尺寸横屏极限检查：基本可操作、不遮按钮 |
| 800×360 | 常见宽屏手机布局检查 |
| 844×390 | 带安全区的宽屏手机模拟 |
| 960×540 | 小电脑窗口 |
| 1024×768 | 平板4:3比例的布局变化检查 |
| 1440×900 | 电脑16:10比例的布局变化检查 |
| 1280×720、1920×1080 | 常规电脑窗口和大屏检查 |
| 2560×1080 | 超宽屏环境延展，不扩大核心交战视野 |

这些是逻辑视口，不是声明某型号手机的物理分辨率或真实安全区。安全区单独模拟四边非零占位。

验收必须覆盖：战斗、主城、招募、英雄目标选择、升级、领奖、失败、广告返回、窗口变化、切后台恢复。至少一轮真实手机触控与低端设备测试不能由鼠标模拟替代；画面顺畅也不代表触控准确或发热正常。

## 资源制作要求

- UI框与按钮采用可伸缩边框或引擎九宫格思路，文字与装饰分层，避免一整张图片包含所有文字。
- 图标提供统一尺寸与留白，必要轮廓在手机缩小时仍可辨认；主城和单位美术继续沿用原创手绘方向。
- 技能预警与命中特效不能只靠细小文字，手机上也要能区分施法、命中、治疗与保护。
- 高分屏可以提高渲染清晰度，但不能直接按高像素密度把按钮做小；性能模式降低粒子等装饰，不降低必要文字与危险提示的可读性。

## 本次结论

把“手机优先、电脑适配、同一核心视口和逻辑”纳入第一份可玩版本。先用响应式布局实现两端共用，正式手机测试及三平台运行再验证，不因为主要在电脑开发就把桌面效果当作手机验收。
