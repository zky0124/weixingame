把临时庇护所 → 简易房屋 → 小型营地 → 定居点设计完整，逐套确认并保存，再按确认的系统制作试玩版。军团、远征和帝国阶段仅保留后续规划；其他系统是否提前开放需逐项决定。

现有总纲仍是跨阶段设定入口；本文件夹负责阶段1细节。各系统已补入工作方案，用户可只提出不喜欢或想改变的地方，助手负责细化、记录并核对系统间衔接。

## 建议讨论顺序

1. 先定01范围和02主城：四节点、终点、时长，以及本次开放哪些系统。
2. 再定03经济、04兵种、05战斗、06回合、07野怪：确保一次完整游玩和资源收支说得通。
3. 接着处理10失败、14存档：和永久死亡、奖励结算联动，不能留到最后临时补。
4. 根据范围处理08英雄、09科技、13广告黑市、15成就；延期的明确记录。
5. 11界面与12美术尽早讨论方向，核心画面样稿在制作阶段先验证，再批量生产素材。
6. 16平台与验收贯穿开发前准备和最后验证，平台规则按当时官方要求核验。

## 谁来补哪些内容

- 用户决定：体验偏好、系统取舍、剧情、兵种英雄特色、失败代价、广告边界和美术喜好。
- 助手拟定：可选方案、规则衔接、属性初值、价格曲线、自动战斗行为、技能目标判断和实现方案。
- 试玩调试：射程、移速、血量、伤害、攻速、怪物数量、刷新间隔、收入、升级等待时间和特效强度。

用户可以回答“你给建议”“你拟初值后测试”“延期到阶段2”。这也是有效决定，不必为每个数字提前猜测。技术方案不要求用户编写。

## 记录与确认规则

1. 已确认：明确来自用户的要求；助手只是复述时不改变其含义。
2. 建议：助手提出、尚未被用户采用；不混入正式规则。
3. 初值待调试：规则和目标已定，允许助手给起始数值并在试玩中调整。
4. 延期：本次不制作，写明何时再讨论；不遗忘也不偷偷加入试玩。
5. 待讨论：尚无结论。若新回答与旧规则冲突，列出冲突再确认，不静默覆盖。

每次讨论后更新对应系统文件、成长表和决策记录；实质修改同步总纲与更新记录。旧建议被替换时注明，避免多份文件互相矛盾。

## 开始制作前的完成条件

- [ ] 四节点的解锁、价格初值、前置条件和阶段结束方式可查。
- [ ] 每项功能明确纳入、延期或不采用。
- [ ] 兵种、敌人、英雄、建筑和技能拥有对应设计卡。
- [ ] 主线与野怪在开始、结束、失败、进入城市时的规则明确。
- [ ] 收入、招募损失、升级和恢复能形成无需广告的可玩循环。
- [ ] 失败、低级英雄永久死亡、重试、退出与存档之间没有矛盾。
- [ ] 广告原奖励、额外奖励、代币及重复领取规则明确。
- [ ] 战场和城市界面所需素材及动作清单明确。
- [ ] 数值可标为初值待调试，不要求开工前已经平衡完成。

## 当前讨论方式

先看简化方案整体，再按用户反馈修改。无需逐题回答。数值先用初值，具体回合配置、技能逻辑、价格和素材规格由助手继续细化；本轮仍只设计，不开始程序制作。
